# Minecart機能 制作意図

このドキュメントは、`Assets/Scripts/Minecart`フォルダおよび関連するスクリプトの制作意図をまとめたものです。

## 概要

`Minecart`機能は、プレイヤーが採掘した資源を地上に運搬するためのシステムです。プレイヤーを追従する複数のトロッコで構成され、プレイヤーのインベントリがいっぱいになると自動的にアイテムをトロッコに移し、トロッコがいっぱいになるとそのトロッコは地上に送られます。

## 各スクリプトの役割

### `Assets/Scripts/Minecart/Minecart.cs`

トロッコ単体の状態とデータを管理するクラスです。

*   **主な役割**:
    *   トロッコのゲームオブジェクト参照 (`gameObject`)
    *   移動コンポーネント (`movement`)
    *   積載している資源の種類と量 (`resources`)
    *   地上への送出後のクールダウンタイム (`time`)
    *   現在の積載量 (`CurrentLoad`)
    *   地上へ向かっているかどうかのフラグ (`isGoingToGround`)
*   **制作意図**:
    *   トロッコに関する情報を一つのクラスに集約することで、管理を容易にすることを目的としています。
    *   `MinecartManager`が複数の`Minecart`インスタンスを効率的に管理できるように、データコンテナとしての役割を担います。

### `Assets/Scripts/Minecart/MinecartManager.cs`

複数のトロッコ全体を管理し、システムの中核を担うクラスです。

*   **主な役割**:
    *   トロッコの生成、追加 (`addnewcart`)
    *   トロッコの総数管理 (`cartunit`)
    *   トロッコの積載上限管理 (`CartCapacity`)
    *   プレイヤーの軌跡を記録し、トロッコがそれを追従するように制御 (`UpdateMinecartPositions`)
    *   資源の積載処理 (`updatevalue`)
    *   積載量が上限に達したトロッコを地上に送る処理 (`SendCartToHome`)
    *   地上に送られたトロッコのクールダウン管理 (`settime`)
*   **制作意図**:
    *   トロッコの群れとしての振る舞い（生成、追従、送出サイクル）を一元的に管理するために作成されました。
    *   プレイヤーは直接トロッコを操作するのではなく、`MinecartManager`を介して間接的にトロッコシステムとやり取りします。これにより、ゲームロジックの関心事を分離しています。
    *   `Update()`内でトロッコの状態を監視し、自動的に運搬サイクルが回るように設計されています。

### `Assets/Scripts/Player/MinecartInteractionSystem.cs`

プレイヤーとトロッコ間のインタラクションを専門に扱うクラスです。（Playerフォルダにありますが、Minecart機能と密接に関連しています）

*   **主な役割**:
    *   プレイヤーと最も近いトロッコを検出 (`GetNearestMinecart`)
    *   プレイヤーのインベントリからトロッコへアイテムを自動転送 (`TransferItemsToMinecart`)
    *   アイテム転送の条件（距離、インベントリ状態など）をチェック
*   **制作意図**:
    *   プレイヤーの操作や状態に応じて、トロッコとの連携をスムーズに行うために作成されました。
    *   `PlayerController`と`MinecartManager`の間に立ち、両者の間の結合度を下げつつ、アイテム転送という具体的なインタラクションを実現する責務を負います。
    *   `Coroutine`を使用して、時間のかかるアイテム転送処理を非同期に行い、ゲーム全体のパフォーマンス低下を防ぐように設計されています。

## 関連アセット

*   **`Assets/Resources/Prefab/Minecart.prefab`**: シーン上にインスタンス化されるトロッコの元となるプレハブです。
*   **`Assets/Scenes/MiningScene.unity`**: `MinecartManager`がシーンに配置され、実際に機能が動作するサンプルシーンです。
