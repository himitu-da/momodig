# Mining機能 制作意図

このドキュメントは、`Assets/Scripts/Mining`フォルダおよびその配下にあるスクリプトの制作意図をまとめたものです。

## 概要

`Mining`（掘削）機能は、プレイヤーがゲームワールド内の地形やオブジェクトを破壊し、資源を収集するためのシステムです。このシステムは、**ScriptableObject**を積極的に活用することで、掘削ツールの種類や性能、掘削範囲などを柔軟に設定・変更できる拡張性の高い設計を目指しています。

## 中心的なスクリプトと役割

### `Assets/Scripts/Mining/Digger.cs`

実際に掘削処理を実行するコンポーネントです。

*   **主な役割**:
    *   `BoxCollider`を利用して掘削範囲を定義します。
    *   指定された範囲内の`Tile`（破壊可能なオブジェクト）を検出し、破壊処理を呼び出します。
    *   掘削アニメーションと連携し、アニメーションイベント (`ExecuteDigFromAnimation`) をトリガーとして実際の掘削処理を実行します。
*   **制作意図**:
    *   掘削の「実行」という責務に特化させることで、ツールの種類やプレイヤーのアクションから独立したコンポーネントとしています。
    *   `SetPendingMiningModule`メソッドを通じて、実行する掘削の形状や範囲を外部（主に`MiningTool`）から動的に設定できるようにし、再利用性を高めています。

### `Assets/Scripts/Player/MiningToolsController.cs`

プレイヤーが所持・使用する掘削ツールを管理するコントローラーです。（Playerフォルダにありますが、Mining機能の中核を担います）

*   **主な役割**:
    *   プレイヤーが使用可能なツールのリスト (`usableMiningTools`) を保持します。
    *   現在選択されているツール (`currentMiningTool`) を管理します。
    *   プレイヤーの入力に応じて、`currentMiningTool.Use()`を呼び出し、掘削のプロセスを開始させます。
*   **制作意図**:
    *   プレイヤーと掘削ツールの間の橋渡し役です。プレイヤーの状態（向きなど）をツールに伝えたり、ツールの切り替えを行ったりするロジックを集約します。
    *   **重要な設計意図として、このコントローラーは具体的なツールの詳細（ピッケル、ドリルなど）を一切意識しません。`MiningTool`という抽象的なインターフェースにのみ依存することで、将来的にどのような種類のツールが追加されても、このコントローラーや`PlayerController`自体を修正する必要がないように設計されています。**

## Toolsサブシステム (ScriptableObjectベース)

`Assets/Scripts/Mining/Tools/`配下のスクリプトは、掘削ツールの振る舞いを定義するための部品（モジュール）群です。

### `MiningTool.cs` (抽象クラス)

全ての掘削ツールの基底となるScriptableObjectです。

*   **主な役割**:
    *   ツールの名前やアイコンなどの基本情報を定義します。
    *   掘削の具体的な振る舞いを定義する`MiningModule`への参照を保持します。
    *   ツール使用時のアクションを定義する`Use()`メソッド（抽象）を持ちます。
*   **制作意図**:
    *   「掘削ツールとは何か」という共通のインターフェース（契約）を定義します。
    *   **この抽象化により、`MiningToolsController`は具体的なツールの種類を意識することなく、一貫した方法でツールを扱うことができます。新しいツール（例: ドリル、爆弾）を追加する際は、`PlayerController`や`MiningToolsController`のコードを変更することなく、新しい`MiningTool`の派生クラスを作成するだけで機能拡張が可能になります。**

### `Pickaxe.cs`

`MiningTool`を継承した具体的なツールの例です。

*   **主な役割**:
    *   `Use()`メソッドを実装し、`Digger`に`miningModule`をセットした後、プレイヤーのアニメーション（"Mine"トリガー）を再生します。
*   **制作意図**:
    *   アニメーションを介して掘削を実行するツールの具体的な実装例です。`Use`メソッドが直接掘削するのではなく、アニメーションイベントに処理を委譲する点が特徴です。

### `MiningModule.cs` (抽象クラス)

掘削の「形状」と「範囲」を定義するScriptableObjectです。

*   **主な役割**:
    *   掘削範囲の中心 (`DiggingCenter`) とサイズ (`DiggingSize`) をプロパティとして定義します。
    *   掘削処理の実行メソッド`Execute()`（抽象）を持ちます。
*   **制作意図**:
    *   掘削の振る舞いをツール本体から分離し、再利用可能な部品とすることを目的としています。「1x1の範囲を掘る」「3x3の範囲を掘る」といった振る舞いを個別の`MiningModule`として作成することで、様々なツールに簡単に割り当てることができます。

### `PickaxeMiningModule.cs`

`MiningModule`の具体的な実装です。

*   **主な役割**:
    *   `centerOffset`と`size`フィールドを持ち、インスペクターから掘削範囲を自由に設定できます。
*   **制作意dto**:
    *   `Pickaxe`などのツールにアタッチされ、そのツールの掘削範囲を決定します。`Execute`メソッドは現在では直接使用されず、主に範囲情報を提供するために使われます。

## 処理の流れ

1.  プレイヤーが掘削入力を行う。
2.  `PlayerController`が`MiningToolsController.UseCurrentTool()`を呼び出す。
3.  `MiningToolsController`が現在選択中の`MiningTool`（例: `Pickaxe`）の`Use()`メソッドを呼び出す。
4.  `Pickaxe.Use()`が、自身が参照している`MiningModule`（例: `PickaxeMiningModule`）をプレイヤーの子オブジェクトである`Digger`にセットする (`SetPendingMiningModule`)。
5.  同時に、`Pickaxe.Use()`がプレイヤーの`Animator`の"Mine"トリガーを起動し、掘削アニメーションを再生する。
6.  掘削アニメーションの特定のフレームで設定された**アニメーションイベント**が`Digger.ExecuteDigFromAnimation()`を呼び出す。
7.  `Digger`は、セットされていた`MiningModule`から掘削範囲を取得し、その範囲内のタイルを破壊する。
